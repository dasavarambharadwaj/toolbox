- (direction) User chose Coaching path; requested both ARCHITECTURE-SPINE.md (terse build substrate) and an accompanying ARCHITECTURE-DESIGN.md (visual solution design explainer).
- (decision) AD-1 Paradigm & Workspace: Hexagonal/Layered Rust workspace with strict boundary isolation: (pure domain library, 0 UI/CLI code), (3-tier dependency engine), (subcommand runner), and presentation adapters (, ).
- (decision) AD-2 Unified Multi-call Binary: Single executable on disk. Invocation with CLI subcommands or piped stdin executes terminal flow; zero arguments or desktop launcher dispatch launches the Slint GUI.
- (decision) AD-3 Zero-Copy I/O: Use memory-mapped file access () for files >1MB, bypassing kernel-to-user buffer copies to achieve near-instant hashing, parsing, and image loading.
- (decision) AD-4 Work-Stealing Multi-Core Parallelism: Use work-stealing thread pools for batch file operations (e.g. converting 50 images in parallel), saturating all CPU cores without UI thread contention.
- (decision) AD-5 Hardware SIMD Acceleration: Standardize on hardware-vectorized crates (BLAKE3 for hashing at 3-5 GB/s, with AVX2/NEON) to maximize throughput on modern CPUs.
- (decision) AD-7 Extension Viewport & Host API: Root app provides a dedicated embedded viewport for extension UI (like an iframe) and exposes an IPC Host API over Unix Domain Sockets for status updates, process lifecycle (kill/query), native dialogs, and storage.
- (decision) AD-6 Render-Thread Isolation: Slint main thread owns event loop; worker computations stream progress via slint::invoke_from_event_loop.
- (decision) AD-8 3-Tier Dependency Engine: Tier 1 host $PATH probe -> Tier 2 user-space static musl fetch (~/.toolbox/deps/) -> Tier 3 manual storage dashboard with explicit user-initiated removal (no auto-pruning).
- (decision) AD-9 Non-Destructive Suffix Output Policy: File conversions and compressions save to source directory with semantic suffix (<name>_compressed.<ext>) by default; overwriting requires explicit confirmation.
